### 2a. The three logged open items

1. **CalDAV is a placeholder but the README sells it as a v1 feature.**
   `Settings → CalDAV` is a "coming soon" surface, yet `README.md` says
   "Bidirectional CalDAV *client* sync IS in v1" — and the UK-nurse walk depends
   on it. This is the biggest gap. Decide + act: either (a) build the bidirectional
   CalDAV client sync (point at Google/Microsoft/Apple/Nextcloud/DAVx⁵ — large;
   stage it as its own multi-phase plan under `docs/plans/`), or (b) if you and
   the user agree it's post-v1, soften the README claim. Default to **building
   it** unless told otherwise — the spec lives in the Phase Y notes referenced
   across `docs/plans/`. Treat external servers with the mock-counterparty
   pattern so it's testable without live creds.

2. **Enforce D.78 S4 in the resolver** (logged in `refactor-solid.md`,
   `#s4-enforcement`). `non_superseable` is parsed by
   `store/SupersedenceConfig.kt` but never reaches `resolver/Calendars.kt::
   CalendarMeta`, so a non_superseable calendar is only preserved by *not being
   listed* in a `supersedes` array (that discipline already broke once → the cat
   bug). Add `nonSuperseable: Boolean` to `CalendarMeta`, populate at all build
   sites (`CalendarRegistry`, `IndexerSnapshotPublisher`, `RepoSettingsHost`,
   test `RichDemoResolverFixture`), filter non_superseable refs out of every
   suppressor's effective supersedes set in `OverlayResolver`, and add a
   regression test (list a non_superseable cal in a supersedes array → assert it
   is never tagged `supersededByCalendar`).

3. **Chip-row DRY + B.4 timezone** (both in `refactor-solid.md` / `iter-3.md`):
   - `#chip-row-dedup`: the wrap-to-next-line chip group is now duplicated ~7×
     (inline `FlowRow`) plus the wizard's private `WrappingChipRow`. Extract one
     shared `ui/components/WrappingChipRow.kt`, route every chip group through it,
     delete the duplicates.
   - **B.4**: event-detail shows the timezone redundantly
     ("Arctic/Longyearbyen · Longyearbyen"). Decide a multi-tz display format
     (when to show IANA id vs friendly city; only-when-differs-from-device) and
     apply it.
